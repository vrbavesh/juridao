# JuriDAO — Full Build Blueprint

**Objective:** Build JuriDAO end to end per `SPEC.md` — contracts, scripts, and frontend — as a one-command hackathon demo on a local Hardhat chain.

**Mode:** Direct mode (git available, `gh` not available, repo not yet initialized → `git init` + commit-per-step rollback, no branches/PRs).

**Root:** `C:\JuriDAO` · **Spec:** `SPEC.md` (canonical requirements; this plan never overrides it)

## 0. Contract-first architecture (read before any step)

There is no HTTP backend in this project (SPEC §1: "Backend: None"). The boundaries that exist are:

| # | Boundary | Canonical artifact (source of truth) | Generated / derived consumers | Owner |
|---|---|---|---|---|
| B1 | Contracts ↔ Frontend | Solidity interfaces `contracts/contracts/interfaces/*.sol` + the `.sol` implementations | `web/src/contracts/abis/*.json`, `web/src/contracts/deployments.json`, `web/src/contracts/generated.ts` (typed ABI + derived interfaces) — **all generated by `contracts/scripts/export-abis.ts`, never hand-edited** | S1 creates interfaces; S7 creates the exporter |
| B2 | Frontend ↔ mock-ipfs | `api/openapi.yaml` (OpenAPI 3.1) | `mock-ipfs/server.js` implements it; `web/src/lib/storage.ts` consumes it; contract test validates responses against it | S1 artifact; S6 provider; S9b consumer |
| B3 | Off-chain documents passing through the chain (deal metaURI, dispute metaURI, evidence item JSON) | `api/schemas/*.schema.json` (JSON Schema) | TS interfaces emitted into `web/src/contracts/generated.ts`; fixture validation in tests | S1 |

### Rules (adapted from contract-first)

1. **Change the artifact first.** Never edit `server.js`, `storage.ts`, or page code to expect a new field/shape before the corresponding `.yaml` / `.schema.json` / `.sol` interface changes. Order: artifact → regenerate → provider → consumer → verify both sides against the artifact.
2. **Generated files are read-only.** If `web/src/contracts/` is hand-edited, the build is wrong. The freshness gate (below) catches this.
3. **Both sides pass against the same artifact before a step is done.** Consumer proof = `npx tsc --noEmit` + `npm run build` (once S8 exists). Provider proof = `npx hardhat test` + (for B2) response validation against `openapi.yaml`.
4. **No duplicated sources of truth.** Event names, enum values, ruling values (0/1/2), commit-hash formula, and status codes appear in exactly one artifact each; `SPEC.md` documents them, code implements them, tests assert them.

### API design rules (boundary B2, mock-ipfs)

SPEC §5 fixes the resources but is silent on status codes and the error envelope; these choices are recorded in `DECISIONS.md` at S1:

- `POST /upload?name=<filename>` → **201 Created**, body `{ "uri": "ipfs://mock-<sha256>", "hash": "<bare sha256 hex>" }`. The URI path segment is `mock-<hash>`; `resolveUri("ipfs://mock-<h>")` → `${VITE_IPFS_URL}/ipfs/mock-<h>`.
- `GET /ipfs/:hash` where `:hash` is `mock-<sha256>` → **200** with raw bytes and `Content-Type` guessed from the `name` param (default `application/octet-stream`).
- **400** `{ "error": { "code": "empty_body", "message": "..." } }` for zero-byte upload; **404** `{ "error": { "code": "not_found", "message": "..." } }` for unknown hash. Same error envelope for all errors. CORS open.
- Idempotent by content: re-uploading identical bytes returns the same URI (dedupe by hash on disk).

### Freshness gate (run at every step that touches a boundary)

```bash
npm run export:abis            # regenerates web/src/contracts/ (available from S7)
git diff --exit-code web/src/contracts   # clean after regeneration, or committed as part of the step
npx tsc --noEmit && npm run build        # consumer half — applies only once S8 exists
```

### Contract change protocol

1. Propose the consumer need and compatibility impact (note in `DECISIONS.md` if it changes a public shape).
2. Edit the canonical artifact (`.sol` interface / `openapi.yaml` / `.schema.json`).
3. Regenerate consumers (`npm run export:abis`).
4. Update provider, then consumer code.
5. Run both-side verification. Merge/commit only when both pass.

## 1. Step graph

```
S1 foundation + artifacts + DECISIONS (incl. declared deviations)
 ├─ S2 JuriToken ──────────────┐
 │    └─ S3 JuriCourt core ────┤   (S3 depends on S2: its tests need a real JURI token)
 │         └─ S4 JuriCourt appeals + settlement ─┤
 │              └─ S5 JuriEscrow ────────────────┤
 ├─ S6 mock-ipfs  (implementation ∥ S2–S5 — depends only on S1's B2 artifact; see isolation rules)
 └─ S7 deploy/seed/export/keeper (depends S2–S5)
      └─ S8 frontend foundation (depends S7, S1 B3 artifacts)
           ├─ S9a courts + staking + rewards   ┐ see isolation rules
           ├─ S9b deals pages                  ┘
           └─ S10 dispute flow (depends S9b, S6)
                └─ S11 appeals + execution + notifications + admin
                     └─ S12 polish + full demo run
```

- **Serial vs parallel:** the default execution mode is **serial, in the order above**. Any step pair marked parallel below may overlap **only** when each parallel step runs in its own isolated git worktree with its own install, and the results are merged and re-verified (both steps' full gates rerun on the merged tree) before either step counts as done. Commit-per-step rollback requires commits to be contiguous step boundaries — interleaved commits from two steps in one working tree are forbidden.
  - *Parallel pair P1:* S6 ∥ S2–S5 (disjoint files: `mock-ipfs/`, `contracts/test/mockipfs.*` vs contract sources; caveat: the mock-ipfs test lands in the same test run — merge only when both sides are green).
  - *Parallel pair P2:* S9a ∥ S9b (disjoint page files; shared components StatCard/Countdown/EmptyState/Toast are all created in S8 first, so no collision — see S8).
  - **S2 ∥ S3 is NOT parallel** — S3's tests require the S2 token.
- **Model tiers:** *strongest* → S1, S3, S4, S11 (boundary design, state-machine/settlement logic, appeal economics). *default* → everything else.
- **Global invariant after every step:** `npx hardhat test` green from S3 onward (root `npm run test` once S7 wires it), `npx tsc --noEmit` + `npm run build` green from S8 onward, no skipped tests, no hand-edited generated files.
- **Rollback:** each step ends with one (or, where checkpoints are declared, several clearly-labeled) git commit(s); revert to the previous step-boundary commit if a later step regresses it.

### S3 — JuriCourt core: staking, disputes, periods, draw, commit/reveal · *strongest* · depends: S2

**Context:** The largest state machine. **Checkpoints (each is its own commit — this is the rollback granularity):**
